# data/

All data lives here. **The repository does not contain any photograph or crop**
(they are too large). This folder holds only the structure and a small unified
index. The images are downloaded from Hugging Face or regenerated by the
pipeline, and every script reads them from the paths below through
`common/config_loader.py`.

## Layout

```
data/
├── photos/                 raw photographs, one sub-folder per individual (INPUT, never committed)
├── crops/                  224x224 face crops produced by YOLO
│   ├── known/  <name>/     the 10 zoo individuals            (used by V1 to V6)
│   ├── bos/    <name>/     the 30 rescue-center individuals   (used by V5; unknown test for V3/V6)
│   ├── new/    <name>/     the 5 new zoo individuals          (used by V6)
│   └── wild/               unlabeled internet crops, the "unknown" background class (V3 to V6)
├── crops.json              unified index of every crop (box, source, review status)
├── wild_images/raw/        unlabeled internet photographs before cropping
└── yolo_dataset/ …         YOLO annotation datasets (auto-generated during training)
```

One sub-folder per individual, named exactly with the animal name. A sub-folder
whose name starts with `_` (for example `_rejected`) is ignored by every script.

## Where the images come from

- **From Hugging Face**: the crops and models are hosted at
  https://huggingface.co/tit0000/OrangIdentifier
- **Or regenerated**: put raw photographs in `data/photos/<name>/` and run the
  extraction step of any version (for example `v1_yolo_nano_resnet50/04_extract_crops.py`
  or `v6_megadesc_arcface_15ind/01_extract_crops.py`). The crops appear under
  `data/crops/` and are indexed in `crops.json`.

## Reviewing crops

Every crop is tracked in `crops.json`. To check or correct the boxes, use the
universal reviewer:

```
python common/review_crops.py
```

It reads `crops.json`, shows each crop with its box, and lets you accept, redraw,
skip, reject or delete. Progress is saved after every action.
